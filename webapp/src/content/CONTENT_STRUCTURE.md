# Структура содержания · 0.12.0

- `diagnoses.json`: 69 тем в 12 разделах. `topicKind` различает диагноз, обзор и памятку. Старые идентификаторы и названия для переноса записей сохранены.
- `medications.json`: 170 карточек, включая 10 `noteOnly` памяток. Отдельные карточки могут описывать лекарство, вещество или добавку — число не равно числу зарегистрированных лекарств.
- `medication-categories.json`: 11 групп для фильтрации. `aliases` — названия и бренды; `searchTerms` — скрытые поисковые выражения, например «ноотропы». Поисковые слова не подтверждают эффективность средства.
- `treatment-guides.json`: 421 написанный разбор «диагноз × препарат».
- `pair-context.json`: всё, из чего собирается общий разбор для остальных 7259 пар из 7680 (48 диагнозов × 160 препаратов). Для каждого диагноза — `prep` («при СДВГ») и `helps` (что помогает). Для препаратов — `medicationRules`: каждый препарат входит ровно в одно правило (`limited`, `not_recommended`, `offlabel` — «не основное лечение», `other` — «назначают по другому поводу»); `usual` — где препарат обычно назначают (иначе берётся из написанных разборов), `purpose` — зачем назначают соматические лекарства, `names` — короткие имена для фраз. Написанный разбор всегда важнее общего: чтобы уточнить пару, добавьте её в `treatment-guides.json`.
- `catalog-provenance.json`: происхождение тематического каталога, прежние и новые идентификаторы.
- `meta.json`: версия приложения и дата редакции.

## Виды связей

| `relationKind` | Значение |
| --- | --- |
| `condition` | Обсуждение цели при этом состоянии |
| `specialist` | Особые показания и условия, требующие отдельного обоснования |
| `cooccurring` | Сопутствующее заболевание или отдельная проблема |
| `limited` | Детских или целевых данных недостаточно |
| `not_recommended` | Ограничения, отсутствие стандартного места или отрицательная рекомендация для указанной цели |
| `safety` | Побочные эффекты, взаимодействия и отдельное соматическое лечение |
| `offlabel` | Только в общих разборах: препарат не входит в основное лечение этого состояния |
| `other` | Только в общих разборах: лекарство назначают по другому поводу |

Поле `goals` содержит пункты обсуждения. При `limited`/`not_recommended` интерфейс называет их «Что стоит уточнить», при `safety` — «Что проверить с врачом». Не превращайте эти пункты в обещание эффекта. `questions` добавляет вопросы, специфичные для разбора. `sources` и `updatedAt` обязательны.

`effectiveMeds` в диагнозе — сохранённое техническое имя ограниченного утвердительного списка. Связи `limited`, `not_recommended` и `safety` туда не допускаются проверкой структуры. Все остальные объяснения доступны через «Разборы других назначений». Обзоры и памятки не включаются в выбор установленного диагноза.


После редактирования: `npm run check:content`, `npm test`, `npm run build`. Не меняйте идентификаторы старых карточек без миграции пользовательских данных.

## Немедикаментозная помощь

`specialists.json` содержит 11 специалистов: `id`, `title`, `shortTitle` (для кнопок и фраз), `whenNeeded` (когда этот специалист нужен вообще), `summary`, `domains`, `helps` (ситуация, метод, наблюдаемый результат), `limitations`, `whatToCheck`, `questions`, `sources`, `updatedAt`.

`nonpharm-support.json` содержит ровно один план для каждой из 69 тем: `diagnosisId`, `intro`, необязательный `priority`, `providers`, `limitations`, `progress`, `sources`, `updatedAt`. В `providers` 224 связи; каждая включает `specialistId`, `goal`, `method`, `role` и необязательный `avoid` — чего не ждать от этого специалиста при этом диагнозе (например, логопедический массаж при аутизме). Порядок в списке — приоритет: сначала `core`, затем `conditional`; при аутизме первым идёт поведенческий терапевт. Роль `core` означает помощь по основной задаче, `conditional` — по дополнительной потребности, а не назначение всем детям. `notFor` — специалисты, которых часто предлагают без доказанной пользы (`limited`, например «нейрокоррекция») или которые обычно не нужны (`not_needed`). Для остальных пар «диагноз × специалист» общий разбор собирается из `whenNeeded` и основных специалистов плана. Обратные ссылки строятся из этих же данных.

`limitations.kind`: `not_indicated` — не подходит для указанной задачи; `limited` — ограничены данные; `harmful` — риск вреда; `adjunct` — дополнительная помощь. Не заменяйте указание ограничений метода утверждением о бесполезности всей профессии. Ссылки на источники и дата пересмотра обязательны. `check:content` проверяет полноту 69 планов, ссылки, уникальность и использование каждого специалиста.

## Скрининги

Необязательное `screeningIds` в диагнозе связывает его с релевантными инструментами. Реестр `lib/screeningContent.ts` задаёт `mode`, возраст и единицу, отвечающих, версию, перевод, инструкции, исходные вопросы / внешнюю ссылку и источники. PHQ-9 / GAD-7 — встроенные формы; M-CHAT-R/F / SDQ / ASSQ / Vanderbilt / RCADS-25 / CRAFFT — запись внешнего результата. YGTSS-R — клинические оценки специалиста. Политика прав и алгоритмы описаны в `docs/SCREENINGS.md`.

Не перефразируйте вопросы стандартизированного инструмента и не меняйте возраст / пороги без проверки источника. Версию формулировок и подсчёта меняют явно. Для будущего обновления версии нужно сохранить чтение прежних записей или написать миграцию: текущая нормализация принимает только известную версию. Нельзя тихо пересчитать старый ответ по новой методике.

`psyparent.screenings.v1` хранит отдельный список результатов с версией оболочки `1`. Значения из localStorage валидируются; вычисленные суммы пересчитываются из ответов. Пропуск не равен нулю. Результаты разных детей / отвечающих не объединяются. `includeInVisit` управляет только включением в экспорт. Удаление памятки не удаляет историю скринингов; удаление всех данных очищает оба раздела.

`measurements` хранит дополнительные числовые показатели, `sourceForm` — фактический бланк / перевод, `clinicianConfirmed` — подтверждение процедуры YGTSS-R. CRAFFT создаётся с `includeInVisit: false`. Исходные версии четырёх прежних инструментов сохранены. Проверки чисел и арифметики новых форм находятся в `extraScreeningScoring.ts`.
